1. Comprendre le circuit (30 secondes)

Aucun lien local entre l'app et la caisse : pas de wifi commun, pas de câble, pas de boîtier. Tout passe par internet, de serveur à serveur.

Caisse (iPad)
Encaisse normalement et envoie ses ventes au cloud Lightspeed, comme d'habitude
→
Cloud Lightspeed
Stocke ventes et commandes du restaurant
→
App Samper
Va chercher les données dans ce cloud, avec l'autorisation donnée une fois (OAuth)

Conséquences pratiques : la connexion peut se faire depuis n'importe où (bureau, 4G), la caisse n'a pas besoin d'être allumée à ce moment-là, et l'accès est en lecture seule : rien n'est jamais écrit dans la caisse.

2. Ce qu'il faut avoir sous la main

  • Un compte sur le portail développeur Lightspeed : developers.lightspeedhq.com. C'est là que se crée l'app OAuth (partie 1). Compte sandbox possible pour tester.
  • L'accès au dashboard Supabase du projet Samper : supabase.com/dashboard. C'est là que se rangent les 4 secrets (partie 1).
  • Ton rôle consultant dans l'app : le guide intégré et le témoin de configuration sont dans Paramètres → Intégrations POS (réservé consultant).
  • Pour chaque restaurant à brancher : les identifiants Lightspeed du client (l'e-mail et le mot de passe de son back-office) - c'est lui qui les saisit, ou toi avec son accord.
Règle d'or. La partie 1 (plateforme) se fait une seule fois pour toute l'app, quel que soit le nombre de restaurants. Ensuite, chaque nouveau client = uniquement la partie 2.

3. Partie 1 - Configurer la plateforme (une seule fois)

A

Créer l'app sur le portail développeur Lightspeed (~5 min)

  1. Va sur developers.lightspeedhq.com et connecte-toi.
  2. Crée une nouvelle app K-Series.
  3. Renseigne la Redirect URI, à l'identique, sans espace ni barre finale :
https://ppmtoiqgajwcdkbnrcll.supabase.co/functions/v1/pos-oauth
  1. Active les 3 scopes : financial-api orders-api offline_access
  2. Après création, note le Client ID et le Client Secret.
orders-api est indispensable : sans lui, l'écran passe cuisine (KDS) ne recevra jamais les commandes, ou l'autorisation échouera avec « invalid_scope ».
B

Enregistrer les 4 secrets dans Supabase (~2 min)

Dashboard Supabase → projet Samper → Edge Functions → Secrets. Ajoute :

Nom du secretValeur
LS_CLIENT_IDLe Client ID noté à l'étape A
LS_CLIENT_SECRETLe Client Secret noté à l'étape A - à coller uniquement ici, jamais ailleurs
LS_REDIRECT_URILa même URL que l'étape A, à l'identique
LS_ENVprod pour une vraie caisse · demo pour le sandbox
Piège LS_ENV. La valeur production s'écrit exactement prod : toute autre écriture (« production », majuscules, espace) retombe silencieusement sur le sandbox. Le Client ID/Secret doivent venir du même environnement que LS_ENV.
C

Vérifier que la plateforme est prête (~1 min)

Les secrets sont pris en compte automatiquement en quelques secondes, sans redéploiement. Deux façons de contrôler : dans l'app, Paramètres → Intégrations POS affiche l'étape « secrets Supabase » cochée ; ou simplement relancer Connecter Lightspeed dans Ventes POS - le message « Secret manquant » doit avoir disparu.

4. Partie 2 - Connecter un établissement (à chaque client)

Tout se fait dans l'app, via l'assistant guidé du module Ventes POS. Le détail écran par écran est dans le guide client : ici, l'essentiel.

1

Sélectionner l'établissement et ouvrir Ventes POS

Vérifie le sélecteur d'établissement en haut de l'app : la connexion est propre à chaque établissement. Puis clique sur Connecter Lightspeed dans la barre en haut du module.

2

Dérouler les 3 étapes de l'assistant

Autoriser : la fenêtre Lightspeed s'ouvre, connexion avec les identifiants du restaurant (ceux du client), accepter les droits. Restaurant : choisir la bonne adresse si le compte en gère plusieurs (étape sautée sinon). Historique : importer les 14 derniers jours.

3

Faire le mapping des plats

Onglet Mapping plats : associer les plats de la caisse aux recettes de l'app (suggestions automatiques). Sans ce lien, la mise en place et la conso ingrédients restent vides.

Ensuite, plus rien à faire : synchronisation automatique chaque nuit. Synchro manuelle possible à tout moment (« Synchroniser maintenant », 7 derniers jours). Si un bandeau rouge « Déconnecté » apparaît un jour : « Reconnecter Lightspeed », 30 secondes, l'historique est conservé.

6. Erreurs : cause et solution

Message ou symptômeCauseSolution
« Secret manquant : LS_CLIENT_ID » (ou autre secret) Les secrets Supabase n'ont jamais été configurés Partie 1, étape B
« invalid_client » Client ID ou Secret erroné, ou pris dans le mauvais environnement (demo / prod) Revérifier les valeurs sur le portail, refaire l'étape B
« invalid_redirect_uri » La Redirect URI enregistrée sur le portail ne correspond pas exactement Copier-coller l'URL de l'étape A sur le portail, sans rien changer
« invalid_scope » Un des 3 scopes n'est pas activé sur l'app du portail (souvent orders-api) Activer financial-api, orders-api, offline_access, puis réessayer
« Autorisation refusée » Les droits ont été refusés dans la fenêtre Lightspeed Relancer et accepter les permissions
La fenêtre Lightspeed ne s'ouvre pas Le navigateur bloque les popups Autoriser les popups pour l'app (icône dans la barre d'adresse), « Réessayer »
Connecté, mais vues cuisine vides Historique non importé, ou plats non associés aux recettes « Importer l'historique (14 j) » + onglet Mapping plats
KDS : « reconnexion Lightspeed requise » Connexion datant d'avant l'ajout du droit commandes (orders-api) « Reconnecter Lightspeed » dans Ventes POS : 30 s, données conservées
Connexion OK mais restaurant introuvable ou données incohérentes LS_ENV pointe sur le mauvais environnement (sandbox au lieu de prod) Mettre LS_ENV = prod avec les identifiants prod, refaire la connexion

Pour approfondir : Dashboard Supabase → Edge Functions → pos-oauth → Logs (chaque tentative de connexion y laisse une trace).

7. Checklist nouveau client

  • L'établissement existe dans l'app et il est sélectionné en haut.
  • Les identifiants Lightspeed du restaurant sont disponibles (compte back-office du client).
  • Assistant déroulé : autorisation, restaurant choisi, 14 jours importés.
  • Mapping plats fait, au moins sur les meilleures ventes.
  • Contrôle le lendemain : « Dernière synchro » datée du matin même dans la barre Lightspeed.
